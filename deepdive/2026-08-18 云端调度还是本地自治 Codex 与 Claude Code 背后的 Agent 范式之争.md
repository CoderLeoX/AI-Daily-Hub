## 核心解读

### 1. 背景与问题

这场争论的底层是同一个根本问题：LLM 不可完全信任，代码仓库不可出错，中间的编排层该把边界画在哪里。Codex 走云端路线：用户下发指令，云端沙箱异步执行，结果回传——心智模型是 CI/CD 的任务队列。Claude Code 走本地路线：长驻终端进程，直接读写真实仓库，多轮工具调用——心智模型是结对程序员。两者都宣称生产可用，但生产环境对可控、可审计、可回滚的硬要求，把哲学分歧逼成了具体的工程选型。

### 2. 设计方案

先把共识说清楚：两者都把"计划—执行—验证"作为内环，且都接入 MCP 统一工具协议——工具调用协议化是这场争论里最大的共识，也是本周主题最直接的落点。真正分叉的是编排层。执行隔离：Codex 把动作放进云端容器，用户机器只是控制端，环境可复现、沙箱内做密钥脱敏；Claude Code 在本地进程内执行，环境即上下文，零拷贝拿到 git 状态、本地服务和全部文件。任务模型：Codex 是 job 模型，入队、执行、通知，支持多任务后台并发；Claude Code 是 session 模型，单进程内连续工具调用，配子代理并行和 checkpoint 回滚。人机边界：Codex 偏向"放手跑完再看 diff"；Claude Code 用 plan/auto 等权限模式前置审批关键写操作，随时可打断。

### 3. 权衡分析

本质是信任边界画在哪：云端把执行和数据隔离在沙箱里，换来可复现、可扩展、攻击面收敛，代价是延迟、成本和真实环境感知缺失——它看不到本地运行的服务、内网依赖和生产环境变量。本地模型交互延迟最低、上下文最准，但把不可信代码放进开发机，安全只能靠权限提示和用户纪律兜底。任务队列贴合批处理与 CI 心智，会话模式适合交互式重构和大型改造，适用场景本就不重叠。把"工具之争"当结论是危险的：离开仓库规模、团队流程和合规要求谈谁赢没有意义。放到金融、运维这类强审计场景，两边都必须外挂人工审批网关——那个网关才是生产形态真正的核心。

### 4. 工程实践

两条路线都在向 headless/CI 集成收敛，说明生产形态是 agent-in-pipeline，不是人机对话。落地盯四件事：状态可回滚——会话或任务必须有 checkpoint（git 提交或快照），失败能 revert；可观测——日志能回放每一步工具调用的输入输出与 token 成本；安全——密钥脱敏、最小权限环境变量、仓库外路径只读；评测——别只信 SWE-bench，为仓库建立本地 golden 任务集并纳入 CI，模型或提示词升级先跑 canary 回归。

## 延伸思考

如果我来做同类系统，会把控制面与数据面拆开：编排器是持久化任务状态机，只负责调度、评估、审计，不执行代码；执行器是无状态容器，输出只通过 git 和 MCP 回写，会话随时可销毁重建。协议分两层：MCP 做设备层接工具，自研 trace 协议做可观察层，记录每步 token、成本和工具结果，支持事后回放——这正好补上争论里缺失的审计链。记忆不塞 prompt，外置到 checkpoint 和任务元数据，长任务靠状态机续跑而非模型硬记。多智能体按模块分派子代理，接口先行、输出校验，不用自由 swarm。最后是原文没提的三个生产要素：成本失控的预算闸门、敏感代码出境的数据边界、不可变审计日志——它们在生产环境比任何 benchmark 都重要。
