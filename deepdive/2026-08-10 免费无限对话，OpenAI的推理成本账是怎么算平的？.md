## 核心解读

### 1. 背景与问题

大模型推理的成本结构是畸形的：decode 阶段受显存带宽限制，每生成一个 token 都要全量读取权重和累积的 KV Cache；长对话下 KV Cache 随上下文线性增长，成为最大的显存黑洞。免费层一旦开放无限对话，平均会话长度和并发度同步恶化，单位 token 成本被成倍放大。原文只报道了政策本身，但把问题摆上了台面：无上限的需求，对上有限且昂贵的 GPU 资源，靠什么兜底？

### 2. 设计方案

把推理栈当作"成本控制系统"来设计，行业已验证的路径有四条：
- 连续批处理：请求级动态插队与摘除，填满 prefill 与 decode 之间的 GPU 空闲气泡，吞吐量成倍提升，这是 vLLM、TensorRT-LLM、SGLang 等主流框架的共同基石；
- KV Cache 分页管理：借用操作系统虚拟内存的分页思想，消除显存碎片，让超长序列在有限显存内驻留；
- 模型分层与路由：简单对话走小模型/蒸馏模型，复杂任务才路由到旗舰 MoE 模型，让平均单 token 成本远低于旗舰模型的标称成本；
- 量化与投机解码：FP8/INT4 权重量化把显存与带宽需求压一个量级，投机解码用小草稿模型并行验证，摊薄单 token 延迟与占用。

OpenAI 这次改动，本质是把以上能力组合成一道"免费层成本边界"：对话次数无限，但每一次对话的预算被工程手段锁死。

### 3. 权衡分析

核心 trade-off 是体验一致性与成本。免费层不承诺与付费层相同的模型质量与上下文长度，"unlimited chats" 不等于 "unlimited tokens"，公平使用限制就是为成本设的另一道闸。放开对话次数、保留上下文与质量闸门，是个聪明的边界选择：把最大的成本变量（KV Cache）控制进单个会话内，避免全局并发无界。行业里还有两类隐藏工程在原文未展开，但它们是"无限对话"真正成立的前提：跨用户复用的 prompt caching，以及无记忆短上下文的会话裁剪策略。

### 4. 工程实践

容量规划从"峰值预留"转向"弹性池化"：免费层流量视为可降级、可丢弃的弹性负载，闲时填充 GPU 利用率，忙时优先保障付费层 SLO，这是典型的双层 QoS。另一个关键点是 prefill 与 decode 分离部署（PD 分离），避免长 prompt 的 prefill 阻塞 decode，同时为 KV Cache 的跨节点迁移留出空间。运维侧的成本计量单位必须是 token 而非请求数——"无限请求"下的核算粒度，只能落到每个 token 上。
