## 核心解读

### 1. 背景与问题

法律工作的 agent 化面临一个通用模型的结构性短板：单轮问答质量高，但长时程任务（跨文档合同审查、多轮证据检索、长链文书起草）的完成率低。问题不在"答得对不对"，而在"能不能持续做对"——长上下文漂移、工具调用状态丢失、中途决策不可回溯，是 agent 场景的三座山。

Harvey 的解法不是提示工程或 RAG 补丁，而是把问题下沉到模型本身：用领域数据对基座做完整后训练，让"长时程执行能力"成为模型行为的一部分，而不是运行时补救。

### 2. 设计方案

Tenet 的架构决策可以拆成三层：

基座层：选用 Kimi K3 开源基座而非自研。Harvey 明确放弃"预训练即护城河"的思路，把预算和注意力全部压在领域后训练上——这是资本效率的选择，也是风险转移：基座能力的天花板由上游决定。

训练层：与 Fireworks 合作完成后训练。Fireworks 提供训练管线和推理托管，Harvey 只负责领域数据、任务设计和评测。训练与部署一体，模型从实验到上线不需要自建 GPU 集群。

目标层：优化目标从"单轮回答质量"转向"长时程任务完成率"。官方口径下，LAB 长时程基准的任务完成率接近翻倍。

### 3. 权衡分析

自研基座 vs 借力开源：自研换来完全控制，但预训练成本以亿计、周期以年计；借力开源把差异化压缩到数据与后训练一个环节，代价是受制于上游迭代——Kimi K3 一旦大版本升级，后训练需要重做，这是"基座锁死"风险。

后训练 vs RAG/微调：完成率翻倍说明长程规划、状态保持这类行为能力无法靠检索增强补足，必须写进参数。但后训练成本高、迭代慢、可解释性差；如果任务退化成单轮分类或抽取，这条路完全划不来。

评测 vs 现实：这是全文最值得警惕的 trade-off。厂商自报"近翻倍"，独立验证却只存活一项——说明多数 benchmark 存在数据泄漏或训练集贴合。垂直模型领域的评测信任体系已经失效，采购决策不能只看官方数字。

回归成本：长时程基准的重跑成本远高于单轮评测，模型每次更新都要付出高额验证代价，评测预算本身成为工程约束。

## 架构师点评

一、值得学的是"护城河重新定位"。预训练时代结束，垂直领域的机会在数据、后训练与产品闭环。Harvey 用 Fireworks 外包基建、用开源基座外包预训练，把全部弹药集中在最稀缺的环节——领域数据和任务设计。法律、医疗、金融的国内团队可以直接照搬这条路线。

二、最该存疑的是评测可信度。一项指标通过独立验证，意味着其余数字目前无法复现。这不是 Harvey 一家的问题，是垂直模型行业的系统性问题。采购方必须自建私有 golden set，把"厂商报分"降级为参考信号。

三、可迁移的设计是优化目标的重构。把评测从"单轮质量"迁移到"任务完成率"，本质是把 agent 的行为能力纳入训练目标。任何做 agent 产品的团队，都应该先定义"完成"再定义"答对"。

四、天花板与锁死并存。Kimi K3 决定模型上限，Harvey 无法突破基座能力；同时基座升级会强迫后训练重做。垂直模型厂商需要把基座切换能力（数据管线与训练脚本可移植）当架构需求来设计。

五、合规张力未解。法律场景要求可解释、可审计、责任可追溯，而端到端后训练模型是黑盒。原文没有给出任何机制设计——这是落地最大的非技术障碍。
