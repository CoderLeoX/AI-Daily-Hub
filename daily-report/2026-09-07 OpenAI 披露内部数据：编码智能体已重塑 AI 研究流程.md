### 2. Perplexity 公开 GPU 嵌入服务栈：Ivy-Tulip-ROSE 三层解耦

**核心**：检索质量上限 = 嵌入模型质量 × 跑在索引上的单位成本。Perplexity 公开三层架构：Ivy（Rust HTTP 网关，负责解析、分词、超大批次拆分）→ Tulip（Rust gRPC 调度与组批）→ ROSE（Python 推理引擎，模型与 CUDA 图执行）。关键洞察：批量嵌入≈算力密集的 prefill，短查询在线嵌入≈访存密集的 decode，因此直接复用 LLM 服务的 prefill/decode 内核，不另建嵌入引擎；小嵌入模型约 512 token 即可喂饱 GPU，组批是效率核心。
**工程影响**：整模型 CUDA 图 + 惰性捕获消除小模型内核启动开销；LazyTensor 异步取数让 CPU 组批与 GPU 执行重叠；嵌入场景去掉 KV cache、以 ragged attention 替代 padding。对照 vLLM 0.22.0（BF16）余弦相似度偏差 <0.1%，但官方未公布生产级延迟/吞吐/成本数据——架构可借鉴，收益需自行实测。
