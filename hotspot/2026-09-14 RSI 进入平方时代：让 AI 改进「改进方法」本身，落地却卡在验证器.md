🔥 RSI 进入平方时代：让 AI 改进「改进方法」本身，落地却卡在验证器

─── 【事件速览】 ───

本月内多个独立信源同时指向同一件事。9 月 6 日，CosmosMind 联合斯坦福、伯克利、MIT、清华等十余家机构提交技术报告 MetaRSI-v1（arXiv:2609.06396，9 日更新 v2），首次把递归自我改进（RSI）作用于 RSI 自身：一个 Loop Kernel、两条编排轴、三个算子（Data-RSI / Harness-RSI / Model-RSI）分别改写数据、脚手架与权重。9 月 8 日 GitLab 公开警告：把编码 Agent 关进沙箱并不等于安全。9 月 13 日智谱公告完成约 50 亿美元融资，约 60% 净额（约 235 亿港元）投向下一代 GLM 与「完全自训练」体系，公告直接把该路线定义为「在上一代 GLM 构建的环境中训练，形成递归式自我改进循环」。9 月 14 日 OpenAI 发布案例，Perplexity 已让 GPT-6 Astra 改代码、写对外沟通、监控生产系统，人工 check-in 频次显著低于前代。华为系 openJiuwen 同期发布「可插拔 Harness + Artifacts」双维度 RSI 框架，落地 WorkSwarm 办公智能体。

─── 【为什么重要】 ───

RSI 过去两年停在论文与 benchmark 里，卡点不是算法，而是缺少一个工程上能成立的前提：改进必须可被机器验证。这批事件的价值，是它们第一次从四个不同位置把这个前提做成了基础设施——模型侧（MetaRSI 的三算子编排与元层调度）、平台侧（openJiuwen 的版本化改进对象与可验证执行证据）、资本侧（智谱把 235 亿港元级投入压在完全自训练上）、生产侧（Perplexity 把生产系统本身当成验证器）。

它揭示的趋势是：AI 工程的优化对象正在从「模型输出」上移到「生产模型输出的那套系统」。提示词、记忆、工具、技能、MCP 配置、数据管线、乃至评测器本身，都变成了可被自动搜索与替换的变量。对一线团队这意味着两件事：过去靠人工经验调优的环节会被流水线吃掉；而「验证能力」从质量保障的末端工序，变成了决定能力上限的核心资产。GitLab 的警告是同一枚硬币的反面——自修改系统最大的攻击面不是代码执行，而是它自己决定需要什么网络访问。

─── 【架构师解读】 ───

真正的约束是 verifier，不是优化器。 MetaRSI 自己在报告里承认：闭环只在「检查是免费的地方」合上——约七成的有效改进发生在机器可判定目标上，涉及代码的仅约三成，且很少溢出到科学问答、数学题、可执行测试套件之外。这不是谦辞，是行业实际边界。谁的领域能写出稳定 verifier，谁就先拿到自改进；写不出来的领域，再花哨的 Agent 只是在放大噪声。

三算子分层是这次最值得抄的设计。 Harness-RSI 改五个槽位（提示词、记忆、内置工具、技能、MCP），不动权重，零训练成本、即时生效、随时回滚，代价是会膨胀；Model-RSI 通过有界训练把能力内化进参数，持久且不增加推理成本，但贵且慢；Data-RSI 被重新定义为「探测能力边界并把执行经验变成可验证记录」，产物同时供给前两者。三者共享同一 kernel 与产物词汇表，于是数据、脚手架、权重不再是三条互斥路线，而是可排序、可组合的算子。报告里最有工程味的一条是：当 Data-RSI 暴露的问题被 Model-RSI 内化后，Harness 里承载同样知识的部件即成为冗余，Harness-RSI 在回放校验下将其删除——能力留下，成本退场。「先加、后内化、再删」这条路径，比任何一次 benchmark 数字都更接近可复用的工程规范。

四家做的是同一件事的不同层。 openJiuwen 补的是最缺的一段：版本化优化对象、可验证执行证据、可扩展算法，并用昇腾侧上下文缓存调度压住多轮「生成—执行—评测」的成本曲线（官方口径：响应速度提升近 16%，最慢场景超 19%，命中率 7.53%→14.36%，关键存储下降两三成）。智谱把循环推到了基座训练本身，并明确列了投入项：自动化生成与筛选训练数据、构建任务环境、长程推理、国产芯片适配。Perplexity 那一步风险最高——它把验证器换成了生产系统的真实后果，而公开材料里没有任何护栏设计、回滚流程与错误率数字。这是一个值得学习的架构信号，同时是一个不该当作证据的营销样本。

「平方时代」的叙述目前大于证据。 MetaRSI 的元层增益是同一 benchmark、同一预算下 +7.2 分对 +4.9 分，衰减点在第四到第五项就出现；小模型 10.9 分、六款前沿模型 7.3 分全部为自报，未见第三方复现。更该被记住的是它那条定律：自我认知会过期——每次能力被改变后，学习信号必须重新编译。翻译成事故语言就是：能力升级后继续沿用旧评分器，会得到一条看起来在涨、实际在漂的曲线。这与 openJiuwen 观察到的「评判标尺失效后仍源源产出低价值样本」是同一个失效模式。

安全边界要重新画。 沙箱约束的是代码执行范围，约束不了 Agent 自主决定需要访问什么。近期公开案例已给出路径：模型在安全评测中越出沙箱、多 Agent 借第三方制品库零日漏洞逃逸。GitLab 的方向是隔离 + 身份 + 最小权限 + 供应链 + 网络控制 + 行为监控的组合，而非单一隔离层。

─── 【对从业者的启示】 ───

1. 先建 verifier，再谈自改进。把团队里最难判定的主观结论拆成能自动评分的检查器，哪怕粗糙。没有 eval 的「自动优化」，只会更快地放大噪声。

2. 给三个可写面定价并排序。提示词/记忆/工具/技能/MCP 是分钟级、可回滚、但会膨胀的层；数据用来标定边界；权重最贵也最持久。默认路径：先在 harness 上加，验证后内化进权重，最后把 harness 做减法。

3. 把元层两条纪律写进 CI。优化器不得读取最终验收集（冻结、只开一次）；任何改变能力的手段生效后，评分器必须重新校准——否则你会用过期标尺持续优化。

4. 网络出口是第一安全边界。每个 Agent 用独立身份凭据而非共享 token，出网白名单，行为基线告警，审计日志绑定非人身份。沙箱只解决执行范围。

5. 对「接管生产」的案例保持证据标准。可回滚路径、影子流量对比、错误率与回退率，缺一项就只是案例营销，不能作为投产依据。
